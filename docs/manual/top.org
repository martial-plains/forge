** How to read this manual
   :PROPERTIES:
   :SUMMARY:  How the manual is organized, and where the help fits
   :END:

Each chapter is a *node* (an Org heading). Nodes are short and link to one
another; follow the links as you need them rather than reading front to
back.

The first chapters are:

- [[*Getting started][Getting started]] — running Forge and opening your first file.
- [[*Keys and commands][Keys and commands]] — how keys reach commands, and how to run them by name.
- [[*Text][Text]] — moving over and acting on words, sentences, paragraphs and pages.
- [[*Images][Images]] — visiting an image file and transforming the picture.
- [[*Canvas][Canvas]] — drawings that plugins make: boards, Bases and graphs.
- [[*Frontends][Frontends]] — the graphical apps, the system file picker and the canvas renderer.
- [[*Display][Display]] — inserting images with the display text property.
- [[*Conventions][Conventions]] — the notation used throughout the manual.

The built-in help is the other half of the documentation:

- ~C-h f~ (~describe-function~) documents one command by name, with its key
  bindings and the commands it refers to.
- ~C-h k~ (~describe-key~) documents whatever command a key runs.
- ~C-h a~ (~apropos-command~) searches command names, and ~C-h d~
  (~apropos-documentation~) searches their documentation as well.
- ~C-h b~ (~describe-bindings~) lists every binding active in the current
  buffers.

** Conventions
   :PROPERTIES:
   :ID:       Conventions
   :CUSTOM_ID: Conventions
   :SUMMARY:  The notation used for commands, keys, options and references
   :COMMANDS: describe-function describe-key apropos-command
              execute-extended-command save-buffer find-file
              keyboard-quit describe-variable
   :END:

The manual uses the same notation as the rest of Forge:

- *Commands* are written ~like-this~ and can be run by name with ~M-x~
  (~execute-extended-command~). ~save-buffer~ saves the current buffer;
  ~find-file~ visits a file.
- *Keys* are written ~like-this~ too, as a sequence to type:
  ~C-x C-s~ saves, ~C-x C-f~ visits a file, and ~C-g~ (~keyboard-quit~)
  cancels whatever is in progress.
- *Options* are written ~forge.opt["name"]~ and can be set from =init.rhai= or
  inspected with ~C-h v~ (~describe-variable~).
- *References* to another node look [[*Top][like this]], and are how you move
  around the manual.

When a paragraph describes a command you have not met, follow its link or
run ~C-h f~ on it before reading on.

** Updating plugins safely
   :PROPERTIES:
   :ID:       package-updates
   :CUSTOM_ID: package-updates
   :SUMMARY:  Review and roll back package updates
   :END:

Use =M-x package-manager= to browse declared, installed, and indexed
plugins. =M-x package-upgrade NAME= reviews and updates one package;
=M-x package-upgrade-all= reviews available index release notes and Git
commit subjects before applying updates. =C-u M-x package-upgrade-all= or
=M-x package-upgrade-all-dry-run= shows the proposed versions, commits, and
build commands without modifying plugin or data files. A failed build,
smoke test, or lock update restores the previous installed artifact. Mark a
declaration with =freeze: true= to exclude it from automatic upgrades; =pin=
also freezes it and selects the pinned Git revision.

~M-x package-log~ shows structured fetch, build, install, upgrade, and
rollback records with timings, source and revision details, and errors.
~M-x package-log-export~ writes the same records as JSON lines. The log is
rotated in the state directory, and credentials in URLs, query strings, and
authentication headers are redacted. Environment values are never recorded.

** Plugin startup profiling
   :PROPERTIES:
   :ID:       plugin-profiling
   :CUSTOM_ID: plugin-profiling
   :SUMMARY:  Find slow plugins and enforce a startup budget
   :END:

~M-x plugin-profile~ shows where plugin startup and later calls spent their
time: per plugin, the cache lookup, a compile on a cache miss, =init=, lazy
start, and each command, event, answer, completion and process/HTTP callback
(count, total and longest). =forge --profile-startup= prints the same report
from the command line and exits, and =--json= makes it machine-readable.

Set ~forge.opt["startup_budget_ms"]~ in =init.rhai= to be warned in
=*Messages*= when plugin startup takes longer. Batch and headless runs fail
with a nonzero exit status when the budget is exceeded; so does
=forge --profile-startup= for a report over budget. Profiling is off by
default, and while it is off the cost is one atomic flag check per call: no
clock read, lock or label allocation.
