Forge runs in a terminal, and has graphical apps for macOS (SwiftUI and
Metal), GNOME (GTK 4) and Windows (WinUI 3).
The GNOME and Windows apps are thin: the editor draws its own
screen, menu bar and tabs as a grid of styled text, and the app shows
that grid, sends keys, text and the mouse back, and provides what only
the system can (the clipboard and the file picker). A canvas arrives in
the grid as a picture, drawn by the shared renderer.

The apps live under =frontends/=. Build the GNOME app with
=cargo build --release= in =frontends/gnome= (it needs the GTK 4
development files), and the Windows app with =scripts/build-windows.ps1=.

*** macOS integration

The macOS app registers plain text, source-code, Markdown and Forge outline
documents with Finder. Use Open With to choose Forge, or drag files onto its
Dock icon; the app queues those opens while the editor starts. Files can
also be dropped onto an editor window. Forge's exported =com.forge.org= type
lets macOS and Spotlight identify =.org= documents as text.

The =forge://open?file=PATH&line=N= URL scheme opens =PATH= and moves to
one-based line =N=. Paths in URLs must be percent-encoded. The Shortcuts
action “Open Document in Forge” accepts a file URL and asks macOS to open it
with Forge. Neither integration requires an App Store or Developer ID
signature. The Services menu offers “Open Selection in Forge”; it opens
selected text as a temporary text document.

The Swift API is split into =forge.desktop= for cross-platform document
opening and =forge.macos= for native operations. The latter can reveal a
file in Finder, show an existing file in Quick Look, post a notification
after permission is granted, and read or publish plain text, RTF and HTML
pasteboard representations. Command-V prefers text from these pasteboard
types and falls back to Forge's kill ring when there is no text. File URL
drops open documents. If Quick Look, a pasteboard representation, or
notification permission is unavailable, the operation is skipped or returns
false rather than preventing editing.

The app follows the system's light or dark appearance and accent color using
dynamic AppKit colors. The JIT exceptions needed by the WebAssembly plugin
runtime are ad-hoc signed locally; no paid developer account, notarization,
or App Store setup is part of the build.

*** The system file picker

The =find-file-dialog= command opens a file, =find-directory-dialog= opens
a folder in Dired and =write-file-dialog= saves the buffer under a new name,
each with the system's own picker, like the file chooser in other editors.
They are in the File menu. When the frontend has no picker (the terminal),
they fall back to the usual minibuffer commands.

*** The canvas renderer

Canvases are drawn on the GPU (wgpu) when one is available, and on the
CPU otherwise; both draw the same scene. =canvas-renderer= says which is
in use.
